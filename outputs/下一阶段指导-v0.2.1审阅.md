## 必修问题（均为 P1）

### 1. 长音被反复触发

位置：src/core/scheduler.ts:156；src/core/tempo.ts collectNotes。

collectNotes 返回与窗口相交的音符并把起点裁到窗口起点，Scheduler 又把结束裁到 lookahead target。每次 tick 都将持续中的音符重新 note-on。120 BPM 的一个 4 拍音，在模拟播放前 1 秒内发出 41 次 note-on；首段 80 ms，后续主要 25 ms。声部没有按 ID 去重，每次新建，会改变包络、音头、响度和声部占用。

要求：将“查询相交音符”与“调度起音事件”分开。正常前进每个音符实例只触发一次，时长保持到音符或片段边界。seek 时的持续音追赶另设策略。实例键应包含片段、音符与循环轮次，不能仅靠源音符 ID。不要用扩大 lookahead 或修改音色掩盖问题。

### 2. 循环时间计算单位错误，且跨界调度滞后

位置：src/core/scheduler.ts:134。

wrapTime 使用拍数除以秒/拍，应该按拍数乘秒/拍转换。120 BPM、0—4 拍循环的首次回绕时间应为 2.06 秒；模拟到 2.07 秒时当前实现仍锚定 0.06 秒，位置为 4.02 拍。即使修正乘法，当前也只在跨界后调度下一轮，存在定时器粒度的迟到。

要求：提前分割跨循环边界的 lookahead 窗口，按绝对音频时刻调度下一轮，妥善处理多轮跳过、非零循环起点及跨界长音；约定截断或续音行为并测试。

### 3. Stop/seek 未取消未来事件

位置：src/audio/studio-processor.js:1066；src/core/scheduler.ts stop/seek/play。

allNotesOff 只释放已存在声部，不删除已入队 note/click/track 消息。最小复现预排一个未来音符后执行 allNotesOff，事件队列仍剩 1 个事件。停止后仍可能出现新声音，seek 后旧位置事件可能混入。

要求：提供 transport generation 或可按来源取消的事件机制。取消旧运输事件，同时管理现有声部释音；区分实时键盘、运输播放和预设试听，不粗暴清空所有来源。previewNotes 当前还调用全局 allNotesOff，会干扰工程播放，也应在此项一起修正。

### 4. 节拍器游标落在非整数拍后漏拍

位置：src/core/scheduler.ts:189。

metroUntil 被设为连续 target，下次从这个小数拍开始每次加 1，随后只有恰好整数时才点击。模拟前 1 秒只排出第一个 click。

要求：维护下一个节拍索引，与已排窗口终点分离；根据拍号确定点击粒度和重音。覆盖 4/4、3/4、6/8，并明确复合拍的点击约定。

### 5. 播放中改变 BPM 会跳拍

位置：src/main.ts:776；src/core/scheduler.ts:112。

UI 先修改 project.tempo，再由 retempo 调用 currentBeat；后者使用新速度换算旧时间。复现：120 BPM 播到第 2 拍改为 60 BPM，新锚点变为第 1 拍。

要求：先以旧映射捕获当前位置，再以新速度设置音频时钟锚点，取消并重排旧事件。改变速度时定义持续音与自动化的处理。

### 6. 离线导出的 solo 和自动化语义不一致

位置：src/core/audio-engine.ts:191、216；src/core/automation.ts。

混音离线渲染强制 solo:false，实时引擎却执行独奏逻辑。实时自动化通过定时采样获得线性插值，离线仅在关键点发值；两个相距很远的点之间，导出不会复现同一条缓变曲线。共用 DSP 不能证明上游事件语义一致。

要求：明确完整混音是否遵循当前 mute/solo，默认应符合所听状态；分轨规则独立说明。将自动化求值放在统一时间轴/音频处理路径，或使用一致且可验证的控制事件序列。验证起点无关键点、seek、lane 删除后的参数恢复与多个 lane 合并。

## v0.2.2 工作顺序

1. 将上述最小复现转为可重复执行、有断言的测试；保留失败证据。现有脚本只是日志诊断，不是自动通过门禁。
2. 先定义音符实例、时钟映射、运输事件取消和跨循环策略，再修 Scheduler 与处理器协议。
3. 修复节拍器和变速；验证快速 play/stop、seek、循环开关及后台恢复。
4. 统一实时/离线的自动化、mute/solo 与音符事件语义。
5. 在生产构建中重跑真实交互，录取实时结果并与离线结果比较，更新验证与进度记录。

验收矩阵：

| 场景 | 标准 |
| --- | --- |
| 120 BPM 的 4 拍持续音 | 每轮一次起音，音符时值为 2 秒，释音另计 |
| 60/90/120/180 BPM，非零起点循环 | 连续至少 20 轮不累积漂移、首拍不漏不重 |
| 未来音符/点击/控制消息已排队后停止或 seek | 旧运输事件不再触发；新位置播放正常 |
| 4/4 节拍器连续 4 小节 | 点击数量、间隔、重音符合约定 |
| 120→60→180 BPM | 当前音乐位置连续，不倒退不跳拍 |
| 两轨，一轨 solo | 实时与混音导出遵循同一独奏规则 |
| 两点音量/滤波自动化 | 中点及全过程实时/离线控制值一致 |
| 边播放边试听预设 | 两者不互相截断或留下未来试听事件 |

音频对比控制采样率、种子、起始状态与尾音。先比较事件日志，再比较渲染信号；不能只检查输出非静音。

## v0.3：声音与创作手感

完成 v0.2.2 后，再推进下列工作，顺序比旧 progress.md 中“先做 WAV 导入，最后试听”更符合用户目标。

1. 从 64 个预设中选 12—16 个标杆，建立实际试听记录：音高/力度/长短音/和弦/重复击打/干湿声/混音用途。先修播放再评音色，避免把重复触发造成的刺耳或颗粒感误归于 DSP。
2. 区分“风格化建模吉他/合成钢琴”和“自然钢弦吉他/钢琴”。现有建模可以保留用于创意音色；自然音色另评估小规模、有分发授权的采样方案。没有采样并不必然不好听，但不能据算法名称认定自然。
3. 将音高测试从固定 ±60 cents 的宽松门槛改为适合音源、音域与估计方法的标准；先校准估计器，再测多个稳定音高。带失谐合成器与 FM 不使用最强谱峰冒充基频。
4. 完成自定义音色/编曲块保存与导入导出，让用户的声音探索可以积累。预设快照须包含效果与宏状态。
5. 完成卷帘框选、复制粘贴、多音符移动/改长/力度与撤销；随后加入自动化点编辑与 Web MIDI、踏板/弯音。
6. 每个编曲块都放到实际组合中试听。数量达标不等于音乐性达标；增加音色/编曲块的去重与搭配记录。

## 随后的 P4 功能补全

WAV 导入与音频轨、素材收集/持久化、基础 EQ/压缩及缺失的混音能力、可关闭的演奏可视化、文件容错与发行验证。当前低通 tone 不等于完整 EQ，tanh 软限幅不等于可调压缩器或 true-peak limiter。

Web 形态继续成立，暂不需要重写框架。EXE 包装应等核心稳定后进行。不要将构建 dist 等同于已部署网站，或等同于完成用户全部要求。
