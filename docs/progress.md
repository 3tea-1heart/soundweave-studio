## 2. 已实现

### 2.1 音频引擎（P1）

- 单一 `AudioWorklet`（`src/audio/studio-processor.js`）统一负责 16 轨音源、插入效果、发送效果、总线与限幅；实时播放、离线导出、Node 渲染测试共用同一份 DSP 代码，没有第二套简化实现。
- 音源（v0.2.1 已按“更接近真实乐器”的方向重做）：
  - 电钢琴：双调制 FM（1:1 琴体 + 2:1 齿音），调制指数分别按 0.23 s / 0.045 s 衰减；独立 3× tine 正弦与音头 knock 噪声；轻度过载。
  - 钢琴：5 个非谐泛音（非谐系数随音高上升），逐泛音独立衰减、力度控制高次泛音亮度；琴槌噪声 + 低通；输出归一化。
  - 钢弦吉他：Karplus-Strong，环路一阶阻尼随 bright 变化，按环路群延时补偿延迟长度；拨弦位置产生梳状陷波；琴体低通与 DC 阻断；闷音使用更快的环路阻尼。
  - 合成器／贝斯：3 振荡器 unison（detune）、polyBLEP 锯齿/方波、双级 24 dB SVF、指数滤波包络、tanh 驱动、子振荡、LFO 颤音与 tremolo、DC 阻断。
  - 鼓机：分层合成。kick 为低频主体 + 二次谐波冲击 + 槌头噪声；snare 为高通/带通噪声 + 双音调 + crack 瞬态；hat / openhat / crash 使用 6 方波金属振荡器 + 高通与空气层；clap 为多段爆发 + 尾音；tom / shaker / perc 均有力度与音色变化。
- 每轨效果：低通 tone、软饱和 drive、单抽头合唱 chorus、音量、声像、静音、独奏、混响发送、延迟发送。
- 总线（v0.2.1）：立体声混响（每声道 8 comb + 3 allpass + 12 ms 预延迟 + 左右交叉）、带反馈高频阻尼的延迟（190 ms）、主输出 DC 阻断 + 平滑 tanh 限幅。
- 消息协议：`note` / `noteOff` / `allNotesOff` / `panic` / `track`（支持 `when` 用于自动化还原）/ `master` / `metronome` / `resetSource` / `bend` / `pressure`；`levels` 每约 8192 采样回传峰值。
- 弯音与触后（v0.4.0）：`bend` 作用于整轨活动声部（±2 半音，低通平滑），`pressure` 控制触后（0–1，增益 +30% 与低通开度 +18%）；四类有音高音源（EP/钢琴/吉他/合成器）实现 `retune()` 重算增量或环路延迟，鼓轨忽略弯音。
- 事件来源与代际（v0.2.2）：每个音符/点击/控制事件带 `src`（`transport` / `click` / `automation` / `preview` / `live`）与 `gen`；`resetSource` 只作废指定来源的旧代际事件，停止运输不再清空实时键盘与预设试听。
- 预览轨（第 16 轨）用于预设试听，用户轨最多 15 条。
- v0.3.0 首音校准：无发声声部时 `Track.setParams` 让新参数立即生效（有活动声部时仍保持每 block 平滑过渡）。修复了切换音色或连续试听两个同类型预设时，第一个音符沿用旧 detune / cutoff 起音的问题（此前会让合成器音高测试偏差 +13 cents、试听首音音色错误）。
- v0.3.0 预设试听：`presetTrackFx()` 让预设内的 chorus / drive 真正作用于预览轨（synth/bass 的 drive 保持 0，避免预设里没有的过载被凭空加入）；`auditionMinLength()` / `auditionNotes()` 按起音时间加长试听乐句，长起音的 pad 不再被截断在音头。

### 2.2 数据与工程（P2）

- 工程 schema v1：轨道、片段、音符、自动化、主总线、循环、拍号、音频素材（`audioAssets`）、音频轨（`track.kind = 'audio'`）与音频片段（`clip.audio = { assetId, offsetSec, gain }`）；音乐时间全部用拍/tick，不用像素或动画帧。音频素材以 Int16 交错 PCM 的 base64 存入工程，时长上限 300 秒，时间轴峰值每 10 ms 一档。
- 工程保存／打开（JSON 下载与文件选择）、自动保存到 localStorage（600 ms 节流）、启动时自动恢复。
- 撤销／重做：快照式 History，上限 60 步。
- MIDI：导出 format 1（PPQ 480）；导入 format 0/1、running status、tempo meta，并按 program 猜测音源类型追加轨道。
- WAV：16-bit PCM 立体声编码；构建期与导出时共用同一编码器。
- WAV 音频导入（v0.5.0）：文件栏「导入 WAV」解码 8/16/24/32 位 PCM 与 32/64 位浮点 WAV（含 `WAVE_FORMAT_EXTENSIBLE`），拒绝 20 位与 64 位整数、非 WAV、超过 2 声道、超过 300 秒或 64 MB 的文件；素材按原生采样率保存为 Int16 PCM；首个导入创建/复用「音频」轨，片段落在播放头最近的吸附点，重叠时自动后移；素材 id 由文件名、采样率与 PCM 内容指纹共同决定（同内容重导入可自动重连被剥离 PCM 的片段）。
- 音频轨持久化（v0.5.0）：手动保存的工程 JSON 内嵌素材 PCM；自动保存（localStorage）剥离 PCM 只留元数据与峰值，刷新恢复后若仍有音频片段引用缺 PCM 的素材，启动时提示缺失数量并要求重新导入。
- 调度器：以音频时钟为基准，0.14 s lookahead / 25 ms tick；音符排程、节拍器、自动化各自使用独立游标与锚点，循环按“当前轮次锚点”换算并在边界切开窗口，后台卡顿 > 0.5 s 自动 resync。变速时先用旧速度捕获位置，再按新速度重锚并取消旧事件。

### 2.3 播放与导出正确性（v0.2.2）

共享模块 `src/core/session.ts` 统一实时与离线的事件来源：

- **长音**：只在音符起点进入排程窗口时起音，持续音不会随窗口推进重复触发。
- **循环**：按轮次锚点换算时间；支持非零循环起点、多轮跳过；跨边界长音截断在边界，释音交给音源包络。
- **停止/跳转**：通过 `resetSource(src, gen)` 取消未来事件，分别处理运输、节拍器、自动化、试听与实时键盘。
- **节拍器**：独立游标 + 整数步进网格；4/4、3/4 每拍一次，6/8、9/8、12/8 每附点四分（3 个八分）一次，小节头重音。
- **变速**：先用旧映射捕获当前拍，再以新速度重锚，避免先改速度导致位置跳拍。
- **实时/离线一致**：离线混音保留工程 mute/solo；分轨忽略其它轨 solo 并静音其它轨；自动化统一按 1/16 拍网格采样，共用 `controlAt()` 求值；删除 lane 时立即回写静态值。

### 2.5 内容库（P3）

- **3 首示例工程**：夜航 Lo-fi（88 BPM，5 轨 28 片段）、City Pulse（122 BPM，5 轨 36 片段）、晨雾（76 BPM，5 轨 29 片段）。

### 2.7 桌面 EXE（v0.6.0）

- `electron/main.cjs`：Electron 主进程。注册特权自定义协议 `app://soundweave/`，直接 `fs.readFile` 读取 `dist/` 并按扩展名返回 Content-Type，避开 `file://` 下 ES module 与 AudioWorklet 被 CORS 阻断；窗口 1440×940（最小 1100×700），`contextIsolation: true` / `nodeIntegration: false` / `sandbox: true`；禁止 `window.open` 与外部导航（http(s) 链接交给系统浏览器）。
- 权限：`setPermissionRequestHandler` / `setPermissionCheckHandler` 仅放行 MIDI（`midi`、`midiSysex`），其余全部拒绝。
- 下载：`will-download` 拦截所有导出（WAV / 工程 / MIDI / 分轨），弹系统「另存为」，默认目录为「文档」；用户取消则取消下载。
- `electron/package.mjs`：`@electron/packager` 打包 win32-x64，只收 `dist/`、`electron/` 与 `package.json`（asar 打包，不含 src / tools / docs / node_modules），产物 `release/SoundWeave-win32-x64/`；temp 目录放在项目同盘（跨盘 rename 会 EPERM）；若 packager 的目录 rename 仍被系统拒绝，则回退到「本地 `node_modules/electron/dist` + `@electron/asar` 手工拼装」，产物结构一致（此时 EXE 无自定义版本信息）。

### 2.8 回溯录制 / 五线谱 / 和弦建议（v0.7.0）

三项都是**纯前端逻辑**，不触碰 AudioWorklet DSP、调度器与 ambient 子系统。

**回溯录制**（`src/core/retro.ts` + `src/main.ts`）：

- `RetroEvent { pitch, velocity, articulation, start(绝对拍), length(绝对拍) }`，滚动缓冲上限 `RETRO_MAX = 64`；`pushRetro()` 追加时把时长钳到 ≥ 1/16 拍，超限丢弃最早的。
- 捕获时机：`liveNoteOn` 在**未处于录制态**时把按键写入 `retroActive`（起点取调度器当前拍，未播放时取播放头）；`liveNoteOff`、停止播放、以及写入前都调用 `finalizeRetro()` / `flushRetroActive()`，用“松键时刻 − 按下时刻”补齐时长。
- 写回：`retroToNotes()` 把绝对拍换算为片段内相对拍（`start - clipStart + clipOffset`），起点按吸附 `quantize()`，时长按 1/16 取整、下限 0.0625，越界丢弃、尾部越界裁到片段结尾。
- 入口：顶栏「回溯」按钮；无合适片段时先走 `ensureRecordingClip()` 补一个录制片段；写入后清空缓冲并 `commit()`（进撤销栈、触发自动保存）。

**五线谱视图**（`src/core/notation.ts` + `src/ui/pianoroll.ts`）：

- `spellPitch(pitch)` → `{ letter(0=C…6=B), alter, octave, step, name }`；`step = letter + (octave-4)*7`，以中央 C 为 0，每级对应一条线/间。默认升号拼写（`LETTER_INDEX` / `ALTER` 查找表），`alterMark()` 输出 ♯/♭ 与重升重降。
- `PianoRoll` 新增 `view: 'roll' | 'staff'` 与 `getView()` / `setView()`；`render()` 在 `view === 'staff'` 且非鼓轨时走 `renderStaff()`。
- `renderStaff()`：高音谱表五线（steps 2/4/6/8/10，E4–F5），按音符范围自动扩展步进区间并绘制上下加线；符头为椭圆、按 step 决定符干朝向；升降号画在符头左侧；左侧标注 C4 / C5；复用 `drawGrid()` 与 `drawRuler(..., 'STAFF')` 保持时间轴对齐。
- 交互分工：五线谱**只读**，选中态用琥珀色高亮，但所有编辑操作仍在卷帘视图；鼓轨与音频轨切过去会被 `setEditorView()` 拦下并提示。

**辅助和弦建议**（`src/core/scales.ts` + `src/main.ts`）：

- `SCALES` 7 种七声音阶（大调/自然小调/多利亚/弗里几亚/利底亚/混合利底亚/和声小调），每种 7 个音程。
- `diatonicChords(root, intervals, sevenths=true)`：按级数取 1/3/5/7 音（`d+2`、`d+4`、`d+6` 对 7 取模），三级/五级/七级同时决定性质；`chordQuality()` 推导后缀（`''`、`m`、`dim`、`aug`、`maj7`、`m7`、`7`、`m7♭5`、`dim7`、`m(maj7)`），`numeralFor()` 生成罗马级数（小写 + `°`）。
- 根音拼写 `spellScaleRoot()` 不按 pitch class 直接取升号名，而是**按级数字母序**（`B♭` 而不是 `A♯`、`E♭` 而不是 `D♯`），保证 `IV Fmaj7`、`V B♭7` 这类拼写正确。
- 实时高亮 `suggestChord(chords, activePc)`：统计每个候选和弦音命中集合的大小，取最高分（平手取低级别）；`activePc` 取播放头所在片段内起点落在 `[播放头, 播放头+1 拍)` 的音符音高（含片段移调）。
- 试听 `auditionChord()`：以 C4 为基准按半音间隔逐音触发 `engine.note()`，走 `src: 'live'` 事件来源，不污染工程数据。

### 2.9 音频长会话自愈（v0.7.1）

排查「用一段时间后界面显示在播，但实际没有声音」时复现到三类**会导致永久静音**的确定性缺陷，全部在 `src/audio/studio-processor.js` 内修复：

1. **坏时间戳堵死事件队列**：`when` 为 `NaN` 的事件排到队首后，`events[0].frame <= blockEnd` 恒为 false，队列再也不消化，之后所有音符都不发声。现在 `frameOf()` 把非法时间戳退回当前帧，出队循环对非有限 `frame` 直接丢弃，并加上 8192 条的上限与「单块最多处理 8192 条」的护栏。
2. **NaN 力度污染长反馈链路**：NaN 样本进入轨道低通状态（`lpL`）与总线 `DCBlock` / `DelayFx` 状态后，这些状态**永远**保持 NaN，整曲静音。现在逐样本兜底（`if (!isFinite(mono)) mono = 0` 等）、参数经 `sanitizeParams()` 只收有限数值、`noteOn` 校验 pitch/力度/时长。
3. **参数写入 NaN 目标值**：`params: { cutoff: NaN, resonance: undefined }` 写入平滑目标后参数永久 NaN。现在 `Track.setParams()` 与非有限参数全部过滤。

另外补了两类「节点失效」的自愈：

- 每个音频块结束检查总线关键状态（音量、隔直、混响、延迟输出），一旦出现非有限值就 `resetMasterState()` 重建混响/延迟/隔直状态并计数（`recoveries`）。
- `AudioWorkletProcessor.process()` 包一层 try/catch：处理器抛异常时先把输出清零、再 `recover()`（清空事件与声部、参数回默认），并按 1 秒限频通过 `port.postMessage({ type: 'error' })` 上报，音频线程继续运行。
- 主线程 `AudioEngine`（`src/core/audio-engine.ts`）监听该错误与 `processorerror`：`nodeBroken` 时在下次 `ensure()` 重建 Worklet 节点；`ctx` 被系统休眠/设备切走挂起时自动 `resume()`（`statechange` 事件与调度器 tick 各兜一层）。`src/main.ts` 收到错误后提示「音频引擎已自动恢复」并重新下发工程状态。

`tools/audio-recovery-tests.mjs` 用 19 项回归覆盖上述路径（见 §3）。

### 2.10 真实采样音源（v0.7.2）

针对「音色同质化且太假」的问题，在保留合成音源（创意/风格化音色）的同时，为四个常用乐器接入**真实录音采样**：

| 库 id | 乐器 | 采样规模 | 授权 |
| --- | --- | --- | --- |
| `piano-kw` | Kawai 立式钢琴 | 31 音高 × 强/弱 2 层 = 63 个，含延音循环点 | CC0 1.0 |
| `guitar-fss` | 钢弦民谣吉他 | 逐半音 + 中/强两层 = 59 个 | GPLv3 + FreePats 采样例外 |
| `bass-yr` | Yamaha RBX 指弹电贝斯 | 逐半音 12 个 | CC0 1.0 |
| `drums-muldjord` | 原声套鼓 | 底鼓/军鼓/通鼓×2/踩镲/镲片 × 3 力度层 = 21 个 | CC BY 4.0 |

实现要点：

- **音频线程**（[studio-processor.js](../src/audio/studio-processor.js)）：新增 `sbank` 消息与 `SampleVoice`。采样以 **Int16** 存储、渲染时才换算浮点（整库 Float32 会占 60 MB 以上音频线程内存）；线性插值变调、循环点回绕、140 ms 释音包络；力度层由清单的 `velMin/velMax` 决定。鼓组采样会带上 `piece`，继续复用踩镲互斥逻辑。
- **主线程**（[sample-bank.ts](../src/core/sample-bank.ts) + [audio-engine.ts](../src/core/audio-engine.ts)）：`fetch` 取 WAV → 自带 16-bit PCM 解析（不依赖 `decodeAudioData`）→ 按库下发。按需加载并缓存，Worklet 节点重建后自动补发；离线导出前同样先下发，实时与导出听到的是同一套采样。
- **回退策略**：采样库缺失、音高超出覆盖范围（钢琴约 C1–C7、吉他 E2–E5、贝斯 D1–D4）或鼓组没有对应键位时，**自动回退到同类型合成音源**，不会静音。
- **预设与默认工程**：新增 4 个采样预设（`piano-upright-kw` / `guitar-steel-fss` / `bass-finger-yr` / `drum-muldjord`），并作为各自类型的默认；新建工程即为「钢琴 + 贝斯 + 鼓机」的采样组合。预设宏只作用于轨道效果（tone/空间/颗粒），因为采样本身已含力度与音色。
- **检查器**：采样轨不再显示无效的合成参数滑杆，改为「采样音源」说明（真实录音、采样数、授权），自动化下拉也不再提供无效的音源参数。

离线导出、分轨导出与实时播放共用同一条采样路径；`tools/sample-tests.mjs` 27 项回归覆盖加载、力度分层、变调方向、循环延音、非循环收尾、鼓组与回退、以及「与原始采样波形相关系数 0.999」的一致性校验。

## 5. 已知限制（如实记录）

1. **音频轨能力边界（v0.5.0）**：只支持导入 WAV 素材后摆放、调 `素材起点`、`片段增益`、复制/删除；没有音频录音、波形内裁切手柄、淡入淡出曲线、片段内变速与素材替换后的自动重连 UI。单个文件上限 64 MB、素材最长 300 秒；仅支持 8/16/24/32 位 PCM 与 32/64 位浮点 WAV，20 位、64 位整数与压缩 WAV（ADPCM 等）会被拒绝。
2. **MIDI 表达可用但有边界**：弯音固定 ±2 半音、作用于整轨（无逐音弯音/MPE）；复音触后按通道压力近似；CC MIDI Learn 只作用于当前选中轨道的参数/效果，映射全局共享（切换音源后不适用则忽略）。
3. **MIDI 设备实测缺口**：本次自动化环境无法授予 Web MIDI 权限，也没有实体控制器；设备枚举、热插拔、真实弯音/触后/CC 端到端未在真实设备上验证（字节流解析与映射逻辑已由 `tools/midi-tests.mjs` 56/56 覆盖）。
4. **MIDI Learn 学习态点击未完成自动化实测**：检查器 UI、按钮存在与 hit-test 已验证，但续接会话中浏览器操作工具不可用，未完成「点击 L → 学习行高亮 → 收到 CC → 建立映射」的端到端点击验证；该路径的映射建立/换算/持久化由 56 项 Node 测试覆盖，UI 点击需人工确认。
5. **自动保存不保存 PCM**：自动保存（localStorage）只写素材元数据与峰值；刷新后音频片段仍在原位，但缺少 PCM 的素材不会发声，启动时提示缺失数量，需重新导入同名同内容 WAV（id 由内容指纹决定，可自动重连）。重导入只补回 PCM、不额外新增片段；同一素材 2 秒内的重复导入会被忽略，避免浏览器连派两次 `change` 时多摆片段。手动保存的工程 JSON 内嵌 PCM，但素材越多工程文件越大。
6. **15 条用户轨上限**（第 16 轨保留给预设试听）。
7. **自动保存使用 localStorage**，超大工程可能触及浏览器配额；没有 IndexedDB/云端方案。
8. **仅实测 Chromium 与 Windows x64**：Firefox、Safari 未验证；EXE 仅提供 win32-x64 便携版（无 MSI/NSIS 安装包、无自动更新、未代码签名，首次运行会被 SmartScreen 提示），macOS / Linux 未打包。
9. **未做移动端布局适配**：界面按桌面工作站设计。
10. **Canvas 指针路径的浏览器自动化覆盖不足**：钢琴卷帘框选拖拽、自动化曲线画布的绘制/拖点/右键删除，其纯函数逻辑已由 `tools/edit-tests.mjs` 28/28 覆盖，但本次浏览器桥无法向 canvas 注入指针事件，UI 指针路径需人工点按确认（键盘路径的复制粘贴、方向键微调已实测）。
11. **自定义音色/编曲块的文件选择未实测**：导出/导入按钮与 JSON 读写逻辑由 `tools/preset-tests.mjs` 41/41 与 `tools/block-tests.mjs` 58/58 覆盖，但自动化环境无法操作系统文件选择框，导入按钮的实际文件读取路径需人工点一次确认。
12. **音频素材不经过音源效果链**：DSP 中音频声部在合成声部 mono 链之后相加，因此音频轨的 `音色低通`/`过载`/`合唱` 与自动化对这些参数不作用于素材；素材只跟随轨道音量、声像、混响发送与延迟发送（检查器已隐藏这些无效的音源参数，避免误导）。
13. **音频轨波形像素未做截图验证**：浏览器实测确认了导入流程、轨道/片段与检查器分区、状态栏与无控制台错误，但本次浏览器桥没有可用截图，波形的逐像素外观需人工看一眼确认。
14. **EXE 的「另存为」对话框未做人工点击验证**：自检模式用 `SOUNDWEAVE_SMOKE_SAVE` 环境变量把 `will-download` 的目标目录改到临时目录，从而绕过系统对话框；正常双击启动时的对话框外观与用户取消路径需人工点一次确认（保存逻辑本身已由自检产出的合法 WAV 文件间接验证）。
15. **五线谱是只读视图（v0.7.0）**：无调号、拍号、符尾分组、连音与 MusicXML；不能在五线谱中编辑音符；只按高音谱表绘制（低音区按加线延伸，没有低音谱表切换）；默认升号拼写，不按调性选择等音写法。鼓轨与音频轨没有该视图。
16. **和弦建议只覆盖自然和弦（v0.7.0）**：不含次属和弦、转位、离调与替代进行；和声小调按自然七和弦拼写；调性与音阶只存在内存中，不随工程保存，刷新后回到 C 大调。
17. **新三项功能的浏览器交互未做自动化实测（v0.7.0）**：「回溯」按钮、卷帘/五线谱切换按钮、和弦芯片点击与实时高亮只做了构建、类型检查与 36 项纯函数回归；本次环境无法对 canvas 与顶栏按钮做端到端点击采集，需人工点一遍确认（和弦条的网格行高已在 v0.7.0 修正为 38 px，修复了插入和弦条后编辑区行高错位）。
18. **无声问题按「可复现的确定性缺陷」修复，未做真实长会话听感验收（v0.7.1）**：三类静音诱因（坏时间戳堵队列、NaN 污染长反馈状态、NaN 参数目标值）已在 Node 侧复现并回归；Worklet 异常重建与 AudioContext 挂起恢复只验证了「节点仍能发声 / 上下文恢复」，未在真实机器上跑数小时并经历休眠、切换音频设备、拔插耳机的完整听感验证。若仍出现「显示在播但无声」，先看状态栏是否出现「音频引擎已自动恢复」提示。
19. **自检模式的确定性依赖（v0.7.1）**：`npm run exe:smoke` 使用独立 `userData` 且不显示窗口；若改成可见窗口，桌面上的真实鼠标/键盘操作会打断自动流程（曾导致状态栏被「生成工程」「移动片段」覆盖、导出采样超时）。
20. **采样音源的取舍（v0.7.2）**：全部为**单声道**（原始录音的立体声像由轨道声像 + 总线混响补偿）；无离键/释音采样，松键为 140 ms 包络淡出；钢琴与吉他只保留 2 个力度层，极弱/极强过渡略硬；鼓组只有底鼓/军鼓/通鼓/踩镲/镲片是采样，拍手、沙锤与 `perc` 仍为合成；采样音域外（钢琴 C1–C7、吉他 E2–E5、贝斯 D1–D4）自动回退合成音源。
21. **采样库体积（v0.7.2）**：`public/samples` 共 55.9 MB（钢琴 30 MB、吉他 20 MB、贝斯 4 MB、鼓 2 MB），`app.asar` 因此从 0.25 MB 增至 56.3 MB；首次选择采样音色时需下载/解码整库（本机为本地读取，浏览器为同源静态文件），加载完成前该轨回退合成音源，不会静音。素材来源与授权见 [samples.md](samples.md)。
